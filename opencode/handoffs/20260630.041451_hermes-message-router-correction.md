## Problem

router rather than the accountable meta-harness operator.

User correction: this docs patch is Vulcan's responsibility, not a direct
Hermes edit.

## Scope

Repository: `projectkoios-bootstrap`

- `AGENTS.md`
- `pi/AGENTS.md`

- `doc/architecture.00.md`

## Required behavior

The docs should state that Hermes:
- is the meta-harness operator, not a passive message router
- makes routing and completion decisions
- checks provenance and authority before consuming or forwarding artifacts
- can execute lightweight repo-local work directly when no specialist is needed
- routes to Athena, Vulcan, or Koios only when specialist ownership is justified
- preserves repo-local execution boundaries

Keep the existing role separation intact:
- Athena owns architecture, planning, ADRs, and ambiguous design questions
- Vulcan owns implementation, tests, validation, and docs patches that follow an
  accepted direction
- Koios owns knowledge curation and durable notes
- Hermes owns orchestration, run control, handoff coordination, and completion
  gating

## Constraints

- Preserve existing uncommitted provenance clarifications in the target files.
- Do not remove delegated-operator provenance guidance.
- Avoid wording that makes Hermes sound like a mailbox or relay service.
- Avoid expanding Hermes into architecture or implementation ownership beyond
  lightweight direct operations already allowed by the meta-harness guidance.

## Acceptance criteria

- `pi/AGENTS.md` title and role statement no longer call Hermes an "order
  router" as its primary identity.
- Root `AGENTS.md` explicitly says Hermes is accountable for routing or
  completion decisions, not just forwarding messages.
- `README.md` and `doc/architecture.00.md` summarize `pi` as a meta-harness
  operator with direct operations and repo-scoped coordination.
- A search for stale phrasing such as `order router`, `passive message router`,

- Vulcan writes an implementation report to `opencode/handoffs/`.
