# Architecture task: handoff creation command

## Objective

Specify a `projectkoios bootstrap handoff new` command for creating correctly
named and correctly headed handoff artifacts from typed templates.

## Context

Codex created multiple handoff artifacts manually during the current session.
The artifact model is valuable, but creating files by hand risks timestamp
mistakes, missing headers, inconsistent status, and unclear routing metadata.

## Candidate command shape

```bash
projectkoios bootstrap handoff new \
  --to Vulcan \
  --from Codex \
  --origin pi \
  --status active \
  --type implementation-brief \
  --topic projectkoios-current-state-cleanup
```

The command should create a file in the appropriate handoff directory and print
the created path.

## Architecture questions

- How should the command map `--to` values to handoff directories?
- Should `--type` select a body template?
- Should the command create empty section stubs or require body content from
  stdin/editor later?
- Should it refuse to overwrite existing timestamp/topic paths?
- Should it integrate with handoff validation immediately after creation?

## Expected Archon output

- architecture-spec
- acceptance-criteria
- implementation-brief
- CLI argument proposal
- template inventory proposal
- non-goals

## Initial acceptance criteria

- New handoff filenames follow the repo convention.
- The five required header fields are always present.
- The command supports at least routing-decision, architecture-question, and
  implementation-brief templates.
- The command does not open an editor or require interactive input for the first
  implementation.
- The command prints the created file path.

## Non-goals

- Do not implement a full artifact database.
- Do not auto-route the handoff to another harness.
- Do not commit created handoffs automatically.
