# Architecture task: handoff validation automation

## Objective

Specify a repo-local automation command that validates handoff artifact hygiene
across `archon/handoffs/`, `opencode/handoffs/`, `goose/handoffs/`, and
`pi/handoffs/`.

## Context

Recent work produced several handoff artifacts across harnesses. The process is
working, but correctness depends on manual checks:

- filename convention
- required header fields
- valid status values
- active versus complete state
- stale active artifacts
- broken repo-local references

This should become executable validation rather than operator memory.

## Architecture questions

- Should this be a new command under `projectkoios bootstrap`, an extension of
  `validate-harnesses`, or a separate validation module?
- Which handoff fields are mandatory for every artifact?
- Should templates and historical handoffs be validated with the same rules?
- What should count as warning versus error?
- Should more than one active handoff per target harness be allowed?

## Expected Archon output

- architecture-spec
- acceptance-criteria
- implementation-brief
- non-goals
- recommended CLI shape
- warning/error classification rules

## Initial acceptance criteria

- A deterministic command validates all handoff files in known harness handoff
  directories.
- The command checks the required header convention:
  - `Origin:`
  - `Created:`
  - `From:`
  - `To:`
  - `Status:`
- Valid statuses are `draft`, `active`, and `complete`.
- Filename format is checked against
  `YYYYMMDD.HHMMSS_<topic>.md`.
- Validation distinguishes blocking errors from non-blocking warnings.
- Existing completed handoffs can pass without needing chat history.

## Non-goals

- Do not create or edit handoff content in this task.
- Do not route or execute downstream harness work.
- Do not introduce external services.
