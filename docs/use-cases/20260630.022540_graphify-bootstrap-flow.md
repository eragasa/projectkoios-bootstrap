## User question

What files and commands are involved in `projectkoios bootstrap init/install`?

## Purpose

Exercise a small stabilization workflow that starts with a repo-structure
question, attempts Graphify first, falls back to direct inspection when Graphify
is unavailable, and leaves behind an executable check for the discovered path.

## Graphify step

Command:

```bash
graphify . --no-viz
```

Observed result:

```text
error: no LLM API key found (125 doc/paper/image file(s) need semantic extraction)
[graphify extract] found 21 code, 125 docs, 0 papers, 0 images
```

Fallback decision: direct repo inspection was used because `graphify-out/graph.json`
was missing and Graphify could not build the mixed code/docs graph without a
configured semantic extraction backend.

## Direct inspection answer

The CLI entry point is declared in `pyproject.toml`:

```toml
projectkoios = "projectkoios.bootstrap.cli:main"
```

The wrapper `scripts/koios` delegates to:

```bash
python -m projectkoios.bootstrap "$@"
```

The command tree is registered in `src/python/projectkoios/bootstrap/cli.py`.
`projectkoios bootstrap init` is implemented by
`src/python/projectkoios/bootstrap/commands/init.py`; it copies top-level
example files from `agents/global/<harness>/*.example` into each harness local
config directory, stripping the `.example` suffix.

The harness destinations are defined in
`src/python/projectkoios/bootstrap/models.py`:

| Harness | Source | Destination |
|---|---|---|
| Hermes | `agents/global/pi/*.example` | `~/.pi/` |
| archon | `agents/global/archon/*.example` | `~/.archon/` |
| opencode | `agents/global/opencode/*.example` | `~/.opencode/` |
| goose | `agents/global/goose/*.example` | `~/.local/share/goose/` |

`projectkoios bootstrap install` is implemented by
`src/python/projectkoios/bootstrap/commands/install.py`. It symlinks Hermes harness
files from the repo into `~/pi/agent/` and then into `~/.pi/agent/`; it also
materializes harness skills from `agents/global/<harness>/skills/` into the
runtime skill directories. `auth.json` is intentionally not managed by install.

The user-facing commands are documented in `README.md` and the original
bootstrap execution decision is recorded in
`docs/archive/architecture/adr/adr.20260629.000000_bootstrap-plan-execution.md`.

## Executable check

Regression coverage lives in `tests/test_bootstrap_flow.py`.

The check verifies:

- `projectkoios bootstrap --help` exposes `init` and `install`.
- `projectkoios bootstrap init` succeeds with an isolated `HOME`.
- `.example` files are copied with the suffix stripped.
- asset directories such as `skills/` are skipped by `init`; skills are owned by
  `install`.

## Success criteria

- The bootstrap-flow question has a clear answer tied to repository files.
- The failed Graphify precondition is recorded rather than hidden.
- A repeatable test protects the documented `init` path.
- `projectkoios bootstrap validate-harnesses` and the focused pytest check pass.
