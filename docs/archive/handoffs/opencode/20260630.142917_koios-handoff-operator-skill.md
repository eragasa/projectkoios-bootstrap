## Background From This Session

This session tried to route a handoff-ledger projection spec through Archon.
The operational problems were:

1. Generic Archon guidance said to use `--branch`, but repo-local workflows
   such as `archon-assist`, `plan-feature`, and the newly tested
   `athena-handoff-spec` either disable worktrees or need live-checkout access
   to uncommitted source handoffs.
2. The source handoff was untracked, so isolated worktrees would not see it.
3. Pi-backed prompt nodes started with `toolCount: 0`, then the detached child
   process exited without completion or output.
4. A Codex-backed prompt node in a minimal workflow also started, then exited
   without completion or output.
5. Archon left stale `running` records after child processes died.
6. Abandoning stale runs required write access to `~/.archon/archon.db`, which
   may require sandbox escalation.
7. `archon doctor` still passed, so the useful diagnosis was not "Archon is
   globally broken"; it was "AI prompt-node execution is not completing in this
   route."

The skill should encode these observations as operating procedure and fast
fallback rules.

## SKILL.md Requirements

Keep `SKILL.md` concise and procedural. It should include:

1. **Session start protocol**
   - inspect `archon/handoffs/`, `opencode/handoffs/`, and `pi/handoffs/`
   - inspect `git status --short --branch`
   - inspect recent commits
   - report pending active/pending/draft artifacts before changing files
   - distinguish stale handoff claims from current git state

2. **Routing decision table**
   - architecture/spec/planning ambiguity -> Athena
   - implementation/tests/validation -> Vulcan
   - knowledge/vault/provenance notes -> Koios
   - direct operations, handoff coordination, run control -> Hermes
   - lightweight direct edits are allowed when no specialist is needed

3. **Archon preflight**
   - run `archon workflow list --json` or validate the specific workflow
   - inspect workflow/provider/worktree behavior when choosing a workflow
   - if input files are untracked and the workflow uses worktree isolation,
     either commit/stage first or use a live-checkout route only when safe
   - do not blindly apply generic `--branch` advice when the workflow declares
     `worktree.enabled: false`

4. **Archon run monitoring**
   - start detached when appropriate
   - capture run ID via `archon workflow runs --json`
   - poll `archon workflow get <id> --json`
   - tail the detached child log
   - check whether the child process still exists when a run remains `running`
   - detect stale-running condition: child process gone, no completion event,
     no artifact output
   - abandon stale records with `archon workflow abandon <id> --json`, using
     escalation when sandbox blocks writes to `~/.archon/archon.db`

5. **Fast fallback rule**
   - after two AI-node Archon attempts in one session exit stale in the same
     way, stop retrying
   - write or update a handoff/deviation note
   - proceed as Hermes with a direct artifact if that is within Hermes scope
   - report exactly what Archon failed to do and what was done instead

6. **Handoff creation discipline**
   - use filename format `YYYYMMDD.HHMMSS_<topic>.md`
   - include required headers
   - include provenance fields when mediation is involved:
     `Acting-As`, `Scope`, `Repository`, `Delegated-Operator`
   - do not collapse Codex into Pi/Hermes or Athena; preserve mediation
     provenance

7. **Stop conditions**
   - no active Archon runs left unintentionally
   - no generated runtime state committed
   - if files changed, report changed files and validation

Move details into the reference files instead of making `SKILL.md` long.

## Helper Script Requirements

### `scripts/session_scan.py`

Purpose: deterministic session-start and handoff-state summary.

Required behavior:

- accepts `--root PATH` defaulting to current directory
- scans `archon/handoffs`, `opencode/handoffs`, `pi/handoffs`, and
  `goose/handoffs` if present
- parses top-of-file handoff headers until the first non-header line
- groups files by `Status`
- emits concise text by default
- supports `--json`
- includes git branch/status summary when run inside a git repo
- marks handoff files missing required headers
- does not mutate files

### `scripts/archon_run_watch.py`

Purpose: monitor Archon runs and detect stale detached runs.

Required behavior:

- accepts `--run-id ID`
- optional `--log PATH`
- optional `--abandon-stale`
- optional `--json`
- calls Archon CLI using `subprocess`, not shell string concatenation
- reads run status via `archon workflow get <id> --json`
- can inspect a detached log path if provided
- detects stale candidates when:
  - run status is `running`
  - no active child process can be found for a known PID, when known
  - no new workflow events appear after process exit
- if `--abandon-stale` is set, runs
  `archon workflow abandon <id> --json`
- reports sandbox/permission failures clearly instead of hiding them
- does not require external Python packages

Note: process inspection can be platform-limited. If reliable PID inspection is
not possible under sandbox restrictions, the script should still report
"process inspection unavailable" and base the stale recommendation on run/log
evidence.

### `scripts/handoff_new.py`

Purpose: create handoff files with correct naming and headers.

Required behavior:

- accepts `--dir`, `--topic`, `--origin`, `--from`, `--to`, `--status`
- optional `--acting-as`, `--scope`, `--repository`, `--delegated-operator`
- optional `--title`
- optional `--body-file` or stdin body input
- generates filename `YYYYMMDD.HHMMSS_<slug>.md`
- slug is lowercase ASCII, hyphen/underscore safe, deterministic from topic
- refuses to overwrite existing files
- writes only under the requested directory
- emits the created path
- has unit-testable pure helpers for slugging/header rendering
