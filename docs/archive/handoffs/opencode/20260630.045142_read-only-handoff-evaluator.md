# Implementation handoff: read-only handoff evaluator

## Objective

Implement the first read-only handoff evaluator from:

- `archon/handoffs/20260630.044545_colored-petri-net-meta-harness-draft.md`

This is the first concrete implementation slice of the colored-Petri-net
meta-harness model. Keep the implementation bounded and validation-focused.

## Scope

Build a read-only evaluator that:
- parses existing handoff headers from known harness handoff directories
- creates DataObjects for artifact tokens, places, provenance, and violations
- reports guard violations for known meta-harness failure modes
- modifies no handoff files

Known handoff directories:
- `archon/handoffs/`
- `opencode/handoffs/`
- `pi/handoffs/`
- `goose/handoffs/`

## Required guard violations

The first slice must detect at least:

1. `hermes-forwarded-without-decision`
   - Hermes forwards unresolved inbox state without producing a
     `routing-decision`, `revision-request`, `completion-decision`, or
     `blockage-report`.

2. `wrong-implementation-owner`
   - Hermes or another non-Vulcan actor claims implementation completion for
     work already routed to Vulcan.

3. `delegated-operator-missing`
   - an artifact mediated by Codex or another operator layer lacks equivalent
     delegated-operator provenance.

4. `codex-as-Hermes-identity-collapse`
   - an artifact claims `Hermes` origin or authority while being produced by Codex
     without preserving delegated mediation.

## Implementation shape

Prefer OOP DataObjects and ActionObjects, consistent with the draft:

DataObjects:
- `ArtifactToken`
- `Place`
- `Marking`
- `Provenance`
- `Violation`

ActionObjects / services:
- handoff parser
- marking builder
- guard evaluator
- violation reporter

Do not build a full Petri net engine in this slice.

## CLI shape

Add or choose the smallest repo-consistent command surface. Candidate:

```bash
projectkoios bootstrap handoff evaluate
```

If that command namespace is too much for the first slice, implement an
internal evaluator plus tests and document the intended CLI in the
implementation report.

## Acceptance criteria

- Existing handoff files can be parsed without chat history.
- Missing or malformed headers produce structured warnings or violations.
- The evaluator reports the known Hermes/Vulcan ownership-collapse patterns.
- The evaluator is read-only and does not mutate handoff files.
- Focused tests cover:
  - valid Athena-to-Vulcan implementation brief
  - invalid Hermes implementation report after Vulcan routing
  - Codex-mediated artifact with delegated provenance
  - Codex-mediated artifact missing delegated provenance
- Vulcan writes an implementation report to `opencode/handoffs/`.

## Constraints

- Do not implement a full Petri net execution engine.
- Do not route this back to Hermes for implementation.
- Do not depend on Archon workflow execution; Archon executor blockage is
  documented in `archon/handoffs/20260630.044544_archon-executor-blocked.md`.
- Preserve existing handoff files unless tests create fixtures.
