# Goose harness: chain-integrity and workflow connectivity gaps

## Discovery context

This report follows the routing-chain deviation documented in
`archon/handoffs/20260630.030355_routing-chain-deviation.md`.
The broken chain never reached the knowledge-capture stage, which
exposed several goose-side gaps.

## Gaps

### 1. No chain-integrity assertion rules

Goose currently has no mechanism to verify that the workflow chain
preceding it is intact. If a knowledge-capture handoff arrives,
goose has no way to check that the archon spec was valid, that
opencode produced a patch and test results, or that pi issued a
completion decision.

Recommendation: add a provenance-verification step to goose's
workflow entry — confirm that the preceding artifacts in the chain
(architecture-spec → patch → test-results) exist and are internally
consistent before creating a knowledge-note.

### 2. No guard for broken chains that never reach goose

The current meta-harness workflow expects goose at the end, but if
the chain breaks earlier (as it did here), goose has no signal that
knowledge capture was missed. The only indication is a stale handoff
directory.

Recommendation: define a "missed capture" detection pattern — if a
completion-decision exists without a corresponding knowledge-note,
goose (or pi routing to goose) should be flagged.

### 3. No explicit trigger for goose participation

Goose is defined as the knowledge-capture end of the standard
workflow, but there's no rule that says "when pi issues a
completion-decision, route to goose first." Currently goose
participation depends on pi remembering to write a handoff.

Recommendation: make goose a required rather than optional terminal
step in the standard workflow, or at minimum add a routing rule in
pi's instructions: "after completion-decision, route to goose if
the output contains new reliable knowledge."

### 4. Stale handoff participation

The most recent goose handoff is from 2026-06-29. Multiple complete
workflow slices since then have no corresponding knowledge-note.
Goose is effectively disconnected from active workflow execution.

Recommendation: inventory completed workflows since the last goose
handoff and determine which should produce durable notes now.

## Status

This report is a finding, not a request for immediate implementation.
It documents goose-side gaps that caused a routing-chain failure to
result in zero knowledge capture.
