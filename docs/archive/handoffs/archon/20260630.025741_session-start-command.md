# Architecture task: session-start automation

## Objective

Specify a `projectkoios bootstrap session-start` command that implements the
Hermes session-start protocol for this repo.

## Context

The root `AGENTS.md` requires session start to:

- check `archon/handoffs/`, `opencode/handoffs/`, and `pi/handoffs/` for new or
  active artifacts
- check git status, branch, and recent commits
- report what is pending before making changes

Codex currently performs these checks manually with shell commands.

## Architecture questions

- Should this command live in the existing Python bootstrap CLI?
- Should it include `goose/handoffs/` even though AGENTS currently names only
  archon/opencode/pi for session start?
- What summary format should be stable enough for agents to consume?
- Should active handoffs be sorted by creation time, target harness, or status?
- Should missing handoff directories be warnings or informational messages?

## Expected Archon output

- architecture-spec
- acceptance-criteria
- implementation-brief
- output format recommendation
- non-goals

## Initial acceptance criteria

- The command reports current branch and ahead/behind state.
- The command reports recent commits.
- The command reports active handoffs by harness.
- The command reports missing handoff directories without failing.
- The command is read-only.
- The command output is concise enough for a new operator session.

## Non-goals

- Do not modify handoff status.
- Do not start Archon runs.
- Do not perform git fetch/pull/push.
- Do not inspect sibling repos by default.
