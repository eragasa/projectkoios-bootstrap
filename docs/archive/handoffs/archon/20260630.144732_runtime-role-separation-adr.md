# ADR review: Runtime/Role separation in models.py

## Context

The `Harness` dataclass in `projectkoios.bootstrap.models` conflates
infrastructure runtime identity (Hermes, archon, opencode, goose) with domain
role identity (Hermes, Athena, Vulcan, Koios). The koios-handoff-operator
skill scripts are about to be implemented and will import from this model.
It is the last clean chance to separate the concerns before new code couples
to the current abstraction.

## What was produced

ADR: `doc/adr/20260630.144732_runtime-role-separation.md`

Proposes splitting `Harness` into `Runtime` (infrastructure) and `Role`
(domain identity) with a transitional `ROLE_TO_RUNTIME` mapping.

## What Athena should do

1. Review and either approve or revise the ADR.
2. If approved, issue an implementation brief to Vulcan covering:
   - Refactoring `models.py` to `Runtime` / `Role`
   - Updating `init`, `install`, `validate_harnesses` to iterate `RUNTIMES`
   - Updating `guards.py` identity checks to use `Role` objects
   - Sequencing: this refactor should complete before or as part of the
     koios-handoff-operator skill implementation.
3. Return acceptance criteria and implementation brief in `archon/handoffs/`.

## Priority

High — this is a pre-requisite for the koios-handoff-operator skill work.
