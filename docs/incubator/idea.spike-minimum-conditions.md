# Idea: Minimum Conditions for a Spike

## Brainstorm

Before starting a spike, we should check whether the work is actually ready to
be investigated instead of still being an idea.

## Possible minimum conditions

A spike should probably exist only when most of these are true:

- there is one clear question to answer
- the question blocks a decision or implementation step
- the scope can fit in a short timebox
- success can be recognized at the end
- the output will change a durable decision, brief, or implementation plan

## If these are missing

Stay in idea mode if:

- the topic is still fuzzy
- there are multiple unrelated questions
- we do not know what result would count as useful
- the work is just exploration without a decision target

## Candidate rule

A spike is allowed only when it has:

- a bounded question
- an expected decision impact
- a timebox
- a promotion target

## Open questions

- How much uncertainty is enough to justify a spike?
- Should a spike always name its downstream ADR or brief target?
- Should spikes expire automatically if they do not produce a decision?
